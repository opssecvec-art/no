The attacker sends a small request to a server using the spoofed IP address of the victim. The server, thinking the request is legitimate, sends the much larger reply to the victim instead.

### Part 3: Specialized, Tactical, & Modern Network-Variant DDoS Techniques

These represent specialized execution methods or protocol-specific variants that bypass traditional single-target scrubbing lines by altering how traffic is distributed or handled.

* **Carpet Bombing (Distributed Subnet Floods):** Instead of concentrating volumetric traffic on a single IP address (which instantly triggers automated scrubbing thresholds), attackers spray a low-intensity flood across an entire IP block (e.g., a /24 IPv4 subnet or /64 IPv6 range). Each individual IP stays just below detection thresholds, but the cumulative effect starves the target network's edge routers or DNS infrastructure.
* **QUIC Protocol / HTTP/3 Floods:** As traffic migrates to HTTP/3 running over UDP-based QUIC, attackers generate massive streams of malformed or connection-ID-shifting QUIC packets. This forces servers to handle expensive cryptographic validation, state tracking, and connection migration without falling back to standard TCP mechanisms.
* **BGP Route-Leak / Hijack Induced Congestion:** Attackers weaponize the Border Gateway Protocol (BGP) by misconfiguring or maliciously poisoning routing announcements. This funnels massive volumes of legitimate global internet traffic through constrained upstream transit links or looping paths, choking the target network through self-inflicted topological congestion.
* **DNS TsuNAME / Loop Attacks:** An advanced evolution of DNS water torturing where attackers register domains configured with cyclic dependencies or malicious alias loops. When resolvers query these records, they become trapped in recursive self-referential loops that consume all available resolver memory and CPU threads.
* **WebSocket & SSE State Floods:** Bypasses stateless HTTP restrictions by establishing thousands of fully authenticated, legitimate TCP/TLS connections via WebSockets or Server-Sent Events (SSE). The botnet then trickles tiny, highly complex state-change messages that force the backend database and application state engines to maintain heavy synchronization locks indefinitely.
* **Zero-Window TCP Attacks:** Attackers complete the TCP three-way handshake and explicitly set the TCP window size to `0`. This tells the server, *"Do not send me any more data; my buffer is full."* The server is forced to pause transmissions and regularly probe the client with window probes, locking up connection buffers across thousands of sockets.

## Part 1: Comprehensive Taxonomy of Known DDoS Attacks

### 1. Volumetric & Amplification/Reflection Attacks (Layers 3 & 4)

These attacks aim to consume all available network bandwidth between the target and the Internet service provider (ISP), or saturate edge firewalls. Amplification exploits connectionless protocols (UDP) with spoofed source IPs to bounce massive traffic payloads off vulnerable third-party servers.

* **UDP Flood:** Floods random or specific ports on a target with User Datagram Protocol packets, forcing the target to check for listening applications and reply with ICMP "Destination Unreachable" packets.
* **ICMP (Ping) Flood:** Overwhelms a target with Internet Control Message Protocol echo requests, forcing the victim's CPU and bandwidth to process and reply to every packet.
* **DNS Amplification:** Sends small DNS record queries (like `ANY` or `TXT`) with a spoofed source IP to open resolvers, generating massive response payloads (amplification factors exceeding 60x).
* **NTP Amplification:** Exploits Network Time Protocol servers (specifically legacy `monlist` commands) to flood targets with large server status statistics.
* **Memcached Amplification:** Abuses public-facing, UDP-enabled Memcached database caching servers, yielding historical amplification factors up to 50,000x.
* **SSDP / UPnP Amplification:** Abuses Simple Service Discovery Protocols on local network devices (smart TVs, routers, IoT) to reflect traffic onto a target.
* **SNMP Amplification:** Exploits Simple Management Network Protocol agents to dump large device management tables to the victim.
* **Chargen Amplification:** Uses the legacy Character Generator Protocol service to loop continuous streams of characters between servers and the victim.
* **CLDAP Amplification:** Exploits Connection-less Lightweight Directory Access Protocol servers, which return large directory query responses.
* **Smurf Attack:** Broadcasts an ICMP ping request to an entire subnet broadcast address using a spoofed source IP, causing every node on that network to reply to the target.

### 2. Protocol & State-Exhaustion Attacks (Layers 3 & 4)

Instead of raw bandwidth, these attacks target stateful connection tables, firewalls, load balancers, and packet-processing buffers.

* **TCP SYN Flood:** Exploits the TCP three-way handshake by flooding a server with SYN packets without completing the final ACK response, exhausting the server's connection backlog tables.
* **TCP ACK / FIN / RST Floods:** Floods stateful devices with unexpected TCP flag combinations, forcing firewalls and routers to spend excessive resources tracking connection states.
* **Fragmented / Teardrop Attack:** Sends overlapping or malformed IP fragments with corrupted offset fields, crashing or freezing the victim's packet reassembly buffers.
* **Ping of Death:** Sends malformed or oversized ICMP packets (exceeding 65,535 bytes) that crash or reboot older operating systems upon reassembly.
* **TCP SACK Panic:** Exploits Linux kernel vulnerabilities regarding Selective Acknowledgment (SACK) ranges, triggering kernel panics and system crashes.
* **TTL Expiry Attack:** Sends packets with very low Time-To-Live (TTL) values designed to expire precisely at a target's internal core routers, exhausting routing CPU cores.

### 3. Application Layer (Layer 7) & Modern Sophisticated Attacks

These attacks target application logic, databases, and APIs. They operate at low bandwidth, closely mimic legitimate user behavior, and bypass traditional volumetric scrubbers.

* **HTTP GET / POST Floods:** Overwhelms web servers with requests for resource-heavy dynamic pages, database queries, or large file uploads.
* **Slowloris:** Opens multiple connections to a target web server and keeps them open as long as possible by sending partial HTTP headers very slowly, tying up all available server worker threads.
* **HTTP Slow POST (R-U-Dead-Yet / RUDY):** Sends legitimate HTTP POST headers specifying a massive content length, then trickles the body byte-by-byte to lock up server connections.
* **Slow Read Attack:** Sends legitimate requests but reads the server's response extremely slowly, forcing the server to keep transmission buffers allocated indefinitely.
* **DNS Water Torture (NXT/RAND Floods):** Generates queries for randomized, non-existent subdomains under a targeted domain, forcing the authoritative DNS server to exhaust processing power searching zone files.
* **Challenge Collapsar (CC) Attack:** Uses hidden proxy networks or legitimate headless browsers directed via botnets to repeatedly trigger resource-intensive database operations (e.g., complex searches, cart checkouts).
* **HTTP/2 Rapid Reset Attack:** Exploits a flaw in the HTTP/2 protocol (CVE-2023-44487) by opening thousands of concurrent streams and immediately sending RST_STREAM frames, generating massive backend load while evading standard rate limits.
* **Yo-Yo Attack:** Targets cloud-native applications utilizing auto-scaling by pulsing traffic bursts to force expensive scale-outs, followed by sudden drops to induce scale-ins, creating financial exhaustion and persistent latency spikes.
* **Advanced Persistent DoS (APDoS):** Multi-vector, highly organized, long-duration campaigns that dynamically rotate vectors (volumetric, protocol, and L7) to keep security teams and automated defenses perpetually off-balance.
* **Hit-and-Run Attacks:** Short, intense bursts of automated traffic designed to periodically knock systems offline, test security boundaries, or distract incident responders from concurrent data breaches.
* **Telephony / TDoS:** Overwhelms VoIP or enterprise phone lines with automated robocalls to disrupt emergency, customer support, or business operations.

### 6. Autonomous Decentralized Edge-Node Swarming (P2P Mesh DoS)

* **Concept:** Eliminating centralized Command-and-Control (C2) infrastructure to create resilient, serverless botnets.
* **Mechanism:** Utilizing self-organizing peer-to-peer (P2P) gossip protocols or blockchain-backed coordination embedded in compromised IoT, vehicular, or smart-home networks. The attack plan is dynamically distributed across millions of decentralized micro-nodes that independently calculate strike windows based on local telemetry, making traditional C2 takedowns ineffective.

#### 6. Autonomous Decentralized Edge-Node Swarming (P2P Mesh DoS)

* **Concept:** Eliminating centralized Command-and-Control (C2) servers for botnets.
* **Mechanism:** Utilizing self-organizing peer-to-peer (P2P) blockchain or gossip protocols embedded in compromised IoT, vehicular, or smart-home networks. The attack plan is dynamically distributed across millions of decentralized micro-nodes that independently calculate strike windows based on local telemetry, making takedowns of C2 infrastructure obsolete.
